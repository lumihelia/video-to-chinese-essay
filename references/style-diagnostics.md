# 中文文风诊断：Video to Chinese Essay Profile

这份文件是 `video-to-chinese-essay` 的中文生成 profile。

它不是一套孤立发展的通用中文规则，而是一个**有版本来源的 vendored profile**：

```text
upstream: chinese-semantic-flow@0.4.2
sync-mode: vendored-profile
task: English long-form source → Chinese essay
```

## Scope

从 upstream 继承并在本任务中执行：

- core proposition first / B-first generation（B 在规划中成立，文章起点由 source 结构决定）；
- forward semantic progression；
- contrast gate（A 必须能指向文本依据，说不出依据时默认从 B 生成）；
- 真实语义关系映射，包括解释机制时保留承担因果的连接词；
- 压缩成标题、小标题或平台标题时保留事件；
- Chinese-native syntax / discourse information order；
- evidence-bound specificity；
- retractable inference；
- 改写时保留原有立场与不确定性。

本文件另外保留英语长内容转中文文章时更具体的 local additions：

- 意合与动词链诊断；
- 名词化、被动语态、所有格与弱动词检查；
- generic `you` 的处理；
- 长文共享观察语气；
- transcript 引用准确性。

当 `chinese-semantic-flow` 的 minor / major 版本修改上述上游语义规则时，重新做 drift review。local additions 不因为 upstream 更新而自动删除。

---

## 0. 先确定 B，再生成

写一句话之前，先确定真正要表达的核心命题 B。

B 已经成立时，直接表达 B，让下一句继续它的因果、机制、后果、条件、时间变化或进一步理解。

**写第一句之前，能用一句话说出 B；B 可以只存在于规划里。** 文章从哪里开始，由 source 的结构和选定的文章形式决定：可以从一个案例、一个问题或讲者的一句话起步，让 B 在后文成形。B-first 约束的是对照结构的来源，不要求每篇文章都把结论放在开头。检查时只看可观察的结果：文章里有没有无来源的 A。

例如，真正要表达的是：

> 上下文设计决定了模型能看到什么，也影响它下一步能做什么。

就直接写这件事。不要先造出：

> 问题不在模型能力……

除非“模型能力是问题”已经真实存在于当前材料或前文。

---

## 1. Contrast Gate：处理真实存在的 A

以下结构本身不禁用：

- 不是 A，而是 B
- 不只是 A，更是 B
- 与其 A，不如 B
- 看似 A，实则 B
- A，但 / 可 / 却 / 不过 B

使用前检查：

1. A 能否指向文本：原 source、前文，或能说出出处、且与当前材料直接相关的公共误解？
2. 处理 A 是否增加理解？
3. B 是否本来就能独立成立？

A 说不出依据，或处理 A 没有信息功能时，从 B 生成。两种错误的代价不对称：该用对照时直说 B，损失很小；没有 A 却用了对照，会替讲者造出一个对手。

### 合法 contrast

原讲者明确说：

> 很多人把这个问题归因于模型规模，但这里真正限制结果的是数据分布。

这里保留对照有信息价值，因为 A 本身就在 source 中。

### 无来源 contrast

source 只说明上下文设计的作用，却没有讨论“模型能力不足”。此时不要自行写：

> 这不是模型能力的问题，而是上下文设计的问题。

直接解释上下文设计如何影响输入、状态和下一步行为。

全文反复使用同一种“立 A → 推翻 A”动作时，也要检查是否已经形成修辞模板。

---

## 2. Forward Semantic Flow：让思想继续向前

两句话之间优先保持真实推进：

- 观察 → 解释
- 判断 → 原因
- 原因 → 机制
- 机制 → 后果
- 后果 → 二阶效应
- 现象 → 条件
- 当前结果 → 下一轮反馈
- 抽象判断 → source 中的具体案例

自检：

> 下一句是在继续当前命题，还是突然掉头修正一个前文没有出现的东西？

后者通常需要重写。

---

## 3. 意合优先，减少逻辑脚手架

英文经常靠连接词和从句显式标记逻辑。中文可以让语序、并置、动作和上下文承担更多关系。

警惕这些词连续承担段落骨架：

- 因此 / 所以
- 但是 / 然而 / 不过 / 可 / 却
- 由于……从而……
- 不仅……而且……
- 值得注意的是
- 更重要的是

这些词可以使用。判断标准是它们是否真的承担必要关系。

不要把一个明显的因果链拆成几句再用“因此”粘回去；能让动作本身推进时，让动作推进。

反方向同样会出错。解释机制、因果链或先后步骤时（技术讲解、方法提炼尤其常见），“因为 / 然后 / 于是 / 所以”常常承担真实关系；为了意合把它们都删掉，机制链会断开，读者反而要自己补。upstream 的一次作者校准里，作者改写一段机制解释时，把 Agent 省掉的这些连接词都加了回来：

> 低温环境会让手机把电量估算得偏低，因为锂电池里的化学反应在冷的时候会变慢，然后内阻变大，于是输出电压就降了下来；而手机是按电压推算还剩多少电的，所以显示的数字就一路往下掉。

判断标准不变：连接词留不留，看它是否承担真实关系，而不是看它显不显性。

## 3.1 中文原生句法与信息顺序

把 English source 重构成中文文章时，最大的翻译腔风险不只来自词汇和连接词。模型也可能先按英语习惯形成完整 proposition，再把词换成中文。

结果会出现：

- 英文主语位置被机械保留；
- 原本可以用动作推进的关系被写成静态属性句；
- 时间 / 地点 / 范围状语只按 source 顺序搬运；
- 英文被动、所有格、名词化继续控制句子；
- 中文本来可以省略的主语、对象和关系被说得过满。

生成一句中文前检查：

1. 当前段落已经知道什么？
2. 这句话真正新增什么？
3. 当前更自然的句内起点是人物、动作、时间、地点、范围、既有话题，还是结果？
4. source 中的动作或感知在现实里怎样发生？
5. 哪些成分可以依靠中文上下文省略？
6. 当前语序是在服务中文篇章，还是在保存英语 proposition 的骨架？

例如，同样在说明某类技术常见于商业环境时：

AI-ish：

> 投影、追踪、巨型灯光这些技术，平时很容易出现在广告、商业活动中。

更贴近人的日常感知时可以写：

> 我们平时经常在广告、商业活动中看到类似投影、追踪、巨型灯光这些技术。

这里不能进一步固化成 `person-first` 规则。以下结构同样自然：

> 到了晚上，一整面建筑外墙会出现互动投影。

> 在这个案例中，人只需要走进光里，在墙上留下影子。

时间、范围、地点或既有话题承担真实 framing function 时，可以自然前置。

稳定规则是：

> **让语序服务于中文里的话题 / 述题、已知 / 新信息、时间地点框架、动作关系和注意力移动。**

一句简化提醒：

> **先用中文理解这句话里的世界，再用中文安排这个世界。**

---

## 3.2 标题与小标题：压缩时保留事件

给文章、章节或平台版本起标题时，压缩修饰和论证，不压缩事件本身。

常见失败：本来完整的问句或陈述，被压成“名词短语 + 抽象动词”的半句，谁在动、动成了什么样都被压掉了。照搬英文 `How X connect` 式标题也会产出同样的半句。

> 写下来的问题，彼此怎么相连

作者接受的写法：

> 写下来的问题是怎么连起来的？

检查：谓语是否带结果（“连起来”而不只是“相连”）；问“怎么”时是否用“是……的”；相互义是否重复（“彼此”+“相连”）；原来是问句的，是否还是问句。

边界：栏目名、系列名、导航式标题本来就是名词性的，不需要补成句子；主语能从语境恢复时仍然可以省略。

---

## 4. 用动词链，不让名词化接管句子

英语长内容常把动作名词化，再用关系词连接。中文重写时把动作还原出来。

警惕：

- ……的本质
- ……的体现
- ……的呈现
- ……的发生 / ……的提出 / ……的形成
- 一堆名词性短语靠“是”连接

翻译腔：

> 这种现象的本质，是用户在面对信息过载时所产生的一种认知防御机制的体现。

更自然：

> 信息一多，人会先筛掉一部分，再简化剩下的，最后干脆不看了。

检查主语和宾语位置是否被“……的……”打包成动作名词。能拆回动作短句时，优先拆开。

---

## 5. 主动语态与所有格经济

英文被动句不需要机械保留成中文“被”字句。

例如：

- `he was promoted` → `他升职了 / 他升为……`
- `the idea was not accepted` → `大家没有接受这个想法`

“被”本身可以自然使用；同一段大量出现且都来自 source 的被动语态时，检查是否只是批量直译。

所有格同理：

- `he raised his hand` → `他举起手`

不要因为英文写了 `his / her / their`，中文就逐次保留“他的 / 她的 / 他们的”。

---

## 6. 弱动词 + 抽象名词

警惕：

- 进行讨论 → 讨论
- 进行分析 → 分析
- 作出决定 → 决定
- 作出回应 → 回应
- 加以解决 → 解决
- 予以说明 → 说明

这些组合不是绝对错误。能用真正动词直接表达时，优先让动词承担动作。

---

## 6.1 固定说法不要逐字搬

英语的固定说法、行业术语，逐字换成中文词，是英译中最常见的词汇层翻译腔。每个字都认识，读者也大致猜得出意思，但这不是中文在这个场合会用的说法。

- gold standard → 不写“金标准”，按意思说“标准答案”“公认的标准”；
- good Chinese → 不写“好中文”，说“自然的中文”“地道的中文”；
- align with → 不必都写成“对齐”，常常就是“一致”“对得上”“按……调整”。

遇到一个“像术语”的中文词，先问：这是中文在这个场合本来会用的说法，还是英语固定说法的逐字对应？如果是后者，回到它在这里的实际意思，用中文重说。

边界：已经进入中文、目标读者普遍在用的译词（机器学习、用户体验）不在此列；某些领域确实通行的术语（例如医学里的“金标准”）按读者群判断；没有通行译法的重要术语，保留英文并在第一次出现时解释。

---

## 7. Generic `you` 不自动变成「你」

英语里的 generic `you` 常表示一般人、使用者或某种情境中的人，不一定是在直接对读者说话。

优先使用：

- 自然省略主语；
- 人 / 人们；
- 使用者；
- 身处其中的人；
- 具体角色。

只有 source 或文章确实需要直接看向读者时，再使用「你」。

「我们」也只在确实存在共同观察位置时使用。不要为了制造亲近感反复把作者与读者强行绑成同一个主体。

---

## 8. 抽象判断必须回到 source

“底层逻辑、深层结构、系统性变化、认知框架、结构性问题、重塑、重构”等词只有在具体机制已经成立时才有价值。

每个重要抽象判断至少能回到一种锚点：

- source 中的明确说法；
- 具体案例；
- 产品 / 技术机制；
- 行为变化；
- 可以核对的 transcript 证据。

source 没有提供的事实不要为了“更具体”而补进去。

合理推断需要保持可撤回，不写成讲者的明确原话。

---

## 9. 目标语气

目标是一位中文作者认真处理完一段长内容之后，写给同样关心这个问题的人看的观察长文。

避免：

- 老师对学生的教学腔；
- 博主对粉丝的训导腔；
- 课程销售式营销腔；
- 每段都总结成金句的 AI 腔；
- 为了“像人”而故意制造口语填充或混乱。

作者可以有判断，但不能靠拔高 source 制造深度。

---

## 10. 引用必须可追溯

只有 transcript 中能找到明确原句时才使用引号。

无法确认逐字准确的内容用转述。翻译后的中文引语也要保持原意，不把普通表达加工成更锋利的“金句”。

引用服务于证据，不服务于装饰。

---

# 完稿自检

自检是写作者的检查，不往文章里添加内容。

## 每次必查

1. 真正成立的核心命题 B 是否清楚？每一处 contrast 的 A 是否能指向 source 或前文，而且处理它增加信息？
2. 句内语序是否服务中文篇章，而不是保留英语 proposition 的骨架？事件是否完整？
3. 每个抽象判断是否有 source 锚点？推断是否被写成讲者的明确说法？引号里的内容是否能回到 transcript？
4. 有没有为了制造深度、力度或金句而改变 source 的判断与不确定性？

## 按需检查

**语义推进**：后一句是否继续前一句，而不是频繁掉头纠正不存在的观点？是否靠连接词搭段落骨架？解释机制时，承担因果的连接词有没有被误删？

**英语残留**：名词化能否还原成动词链？被动语态和所有格是否机械迁移？“进行 / 作出 / 加以 / 予以 + 抽象名词”能否恢复成直接动词？有没有把英语固定说法逐字搬成中文词？中文可以省略的主语 / 对象是否被重复说满？

**人称**：generic `you` 是否被机械翻成「你」？「我们」是否真的有共同主体依据？

**标题**：标题与小标题是否被压成“名词短语 + 抽象动词”的半句？

整篇文章是否在中文里向前运动，而不是保留英语论证与句法脚手架？
